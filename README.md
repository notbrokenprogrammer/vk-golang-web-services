## Каналы и горутины

Во втором задании реализовал **`spammer.go`**: связал этапы обработки каналами, распараллелил запросы и организовал корректное завершение горутин.

| Этап | Что делает |
| --- | --- |
| `RunPipeline` | Соединяет этапы каналами, запускает их и закрывает выходы после завершения работы |
| `SelectUsers` | Получает пользователей по email параллельно и удаляет повторы по ID |
| `SelectMessages` | Запрашивает письма группами по два пользователя, включая последнюю неполную группу |
| `CheckSpam` | Проверяет письма через пять рабочих горутин |
| `CombineResults` | Собирает ответы и сортирует их: сначала спам, затем остальные письма, внутри групп — по ID |

На практике работал с `chan interface{}`, `sync.WaitGroup`, мьютексами, передачей данных между этапами и проверкой гонок через `-race`.

**Разделение авторства:** в папке `spammer/` моя реализация находится в `spammer.go`. Вспомогательные функции в `common.go` и локальные тесты в `main_test.go` предоставлены курсом и сохранены без изменений. Для первой работы мой код находится в `text-game/main.go`, а тесты также взяты из курса.

## Проверка

Работы — отдельные Go-модули. Для текущей реализации `spammer` нужен **Go 1.22 или новее**: горутины используют переменные цикла с отдельным значением для каждой итерации.

**Текстовая игра**

```bash
cd text-game
go run .
go test -v
```

**Конвейер проверки писем**

```bash
cd spammer
go mod tidy
go test -v -race
```

`go mod tidy` загружает зависимость локальных тестов — `testify`. Конвейер запускается тестами; отдельный интерактивный `main` для этого задания не требуется.

<details>
<summary>Проверка отдельных частей конвейера</summary>

```bash
# Соединение этапов и передача данных
go test -v -race -run '^TestPipeline2?$'

# Уникальность пользователей и псевдонимы email
go test -v -race -run '^(TestAlias|TestUsersRace)$'

# Вся цепочка: результат, количество запросов и время
go test -v -race -run '^TestTotal$'
```

</details>

Локальные тесты и тесты на платформе курса отличаются. Прохождение локальных проверок не означает автоматическую сдачу задания на платформе.
