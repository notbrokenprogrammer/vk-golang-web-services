# Проверка писем на спам

Домашнее задание ко второй лекции курса VK «Разработка веб-сервисов на Golang». Практика конвейерной обработки данных с каналами и горутинами.

## Мой вклад

Реализовал пять функций в [`spammer.go`](spammer.go). [`common.go`](common.go) содержит готовые функции курса, имитирующие базу пользователей, сервис писем и антиспам. [`main_test.go`](main_test.go) содержит локальные тесты курса. Оба файла сохранены без изменений.

## Обработка данных

| Функция | Вход | Выход | Особенности |
| --- | --- | --- | --- |
| `RunPipeline` | Функции этапов | Завершённая цепочка обработки | Каждый этап работает в горутине; соседние этапы используют общий канал |
| `SelectUsers` | Email (`string`) | `User` | Параллельные запросы, удаление повторов по ID, защита общей `map` мьютексом |
| `SelectMessages` | `User` | `MsgID` | Параллельные запросы группами по два пользователя; обработка остатка |
| `CheckSpam` | `MsgID` | `MsgData` | Пять рабочих горутин читают общий входной канал |
| `CombineResults` | `MsgData` | `string` | Два среза для спама и остальных писем, сортировка ID по возрастанию |

Псевдонимы email разрешает готовая функция `GetUser`. Моя реализация сравнивает возвращённые ID, поэтому один пользователь попадает в следующий этап только один раз.

`RunPipeline` закрывает выходной канал после возвращения функции этапа. Этапы с внутренними горутинами дожидаются их завершения через `WaitGroup` до возвращения.

Итоговая строка имеет формат:

```text
true 123
true 5555
false 140
false 3000
```

## Что отрабатывал

- Передачу значений через каналы и чтение до их закрытия.
- Запуск горутин и ожидание их завершения.
- Защиту общей `map` при проверке и добавлении пользователя.
- Объединение запросов в группы и ограничение параллельных проверок спама.
- Сортировку результатов и поиск гонок данных с помощью `-race`.

## Проверка

Нужен **Go 1.22+**: код использует переменные цикла с отдельным значением для каждой итерации. Горутины запускаются через `go`, а их завершение учитывается через `WaitGroup.Add`, `Done` и `Wait`. Тесты используют `github.com/stretchr/testify/assert`.

Из корня репозитория:

```bash
cd spammer
go mod tidy
go test -v -race
```

Полная цепочка отдельно:

```bash
go test -v -race -run '^TestTotal$'
```

Готовые сервисные функции печатают логи запросов. Итог теста обозначается `PASS` или `FAIL`; сообщения `WARNING: DATA RACE` указывают на конфликт доступа к общей памяти.
